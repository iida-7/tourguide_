# PRD — 유럽 패키지 감정원 (The Package Inspector)

> **버전**: v1.3 (소스코드·`DESIGN.md` 기준 현행화)  
> **최종 갱신일**: 2026-10-29  
> **배포 환경**: Next.js 16 (App Router), Vercel/Localhost 배포, DB 없음. 일정 분석(룰 엔진)은 브라우저 로컬 연산(운영비 0원). 단, 룰 엔진이 판단하지 못한 **모호 문장에 한해** 선택적 Gemini AI 보조 판독이 외부 API(`generativelanguage.googleapis.com`)를 호출함 (§3.3 참조)  
> **한 줄 정의**: 유럽 패키지여행 일정표를 통째로 붙여넣으면, **원문 보존 일정표 + 4대 관람 방식 팩트체크 스탬프 + 6대 레이더 스탯 + 숨은 비용 영수증 + 생존 인벤토리**를 1초 만에 즉시 감정·시각화해 주는 웹 애플리케이션

## 1. 프로젝트 개요 및 핵심 목표

### 1.1 배경 및 목표
- 유럽 여행 경험이 없는 소비자도 여행사 일정표의 실제 가치와 숨은 비용, 체력 부담을 즉각 직관적으로 이해할 수 있도록 돕는다.
- 여행사 특유의 모호한 문구("조망", "포토타임", "차창", "외관")를 팩트체크하여 **진짜 내부 입장인지, 밖에서 사진만 찍고 지나가는지** 명확히 구분한다.
- **3층 지식 커버리지 & 폴백 원칙**:
  - **1층 (일정 정리 100% 보존)**: 원문의 일차와 내용은 누락 없이 그대로 보존
  - **2층 (도시·국가 개요)**: 장소별 상세 해설이 없더라도 방문 도시 및 국가의 핵심 개요로 안내
  - **3층 (방문지 팩트 해설)**: 명소별 공식 출처 URL 및 관람 모드 팩트 해설 연결

### 1.2 핵심 성공 지표 (KPI) 달성 현황

| # | 지표 항목 | 목표 기준 | 소스코드 구현 현황 |
|---|---|---|---|
| 1 | **응답 속도** | 20,000자 이하 기준 **1초 이내** 결과 렌더링 | **룰 엔진 구현 완료**: 순수 브라우저 인메모리 룰 엔진(`inspector-engine.ts`). 단, Gemini 보조 판독이 켜진 경우 네트워크 왕복 시간만큼 추가됨. 정식 측정 기록은 아직 없음 |
| 2 | **원문 보존성** | 입력된 일정 라인의 누락 0건 | **달성**: 라인 번호(`lineNum`) 추적 및 원문 라인 100% 보존 매핑 |
| 3 | **팩트 및 출처** | 검증된 명소의 공식 웹사이트 출처 표기 | **달성**: 루브르(`louvre.fr`), 융프라우(`jungfrau.ch`), 바티칸(`museivaticani.va`) 등 공식 도메인 출처 자동 연결 |
| 4 | **보안 및 비용** | 외부 유료 API 의무 호출 0건, 운영비 0원, 외부 DB/서버 저장 없음 | **구현됨(범위 조정)**: 분석·결과는 브라우저 로컬(`sessionStorage`)에 한정. Gemini 무료 티어 보조 판독은 **모호 문장 텍스트만** 전송하는 선택 기능이며, 키가 없으면 호출 자체가 일어나지 않음 |
| 5 | **파싱 호환성** | 한국 주요 여행사 일정 형식 인식률 95% 이상 | **패턴 지원 구현**: `제 N일`, `Day N`, `N일차`, `[N일]` 등 다중 정규식 자동 분할. 95% 수치는 샘플 검증 기록이 없어 **미검증** |
| 6 | **지역 커버리지** | 서유럽/동유럽/지중해 주요 15개국 인식 | **부분 달성**: 20여 개 핵심 도시 데이터베이스 및 국가 플래그 매핑 내장. 국가 수 기준 충족 여부는 별도 확인 필요 |

## 2. 기술 스택 및 아키텍처

- **Framework**: Next.js 16.4.3 (App Router, 프로덕션 빌드는 `next build --webpack`)
- **UI & Styling**: React 19, Tailwind CSS v4, Base UI (`@base-ui/react`), Lucide React
- **Design Concept**: 레트로 인스펙터 & 보증서 감성 — 컬러·타이포·컴포넌트 규격의 단일 기준은 `DOCS/DESIGN.md` (Paper `#f8fafc` / Ink `#0f172a` / Navy `#1e3a8a` / Stamp Gold `#b45309`, 하드 섀도우)
- **Typography**: Space Grotesk(헤드라인) · Work Sans(본문) · JetBrains Mono(배지·메타데이터), 한글은 Noto Sans KR 폴백
- **State & Storage**: Browser `sessionStorage` (분석 결과·원문 캐싱 및 세션 유지), `localStorage` (사용자가 입력한 Gemini API 키)
- **Server**: Next.js Route Handler `app/api/gemini-verify` (서버 `.env`의 `GEMINI_API_KEY` 또는 사용자 키로 Gemini 호출을 중계; 키 값은 브라우저에 전달되지 않음)
- **Package Manager**: `pnpm` (v12.3.4, `package.json`의 `packageManager` 기준)

## 3. 화면별 상세 기능 및 명세

### 3.1 화면 1: 일정표 입력 화면 (`/` - `app/page.tsx`, `components/inspector/package-input.tsx`)

| 영역 | 기능 구성 요소 | 동작 및 구현 명세 |
|---|---|---|
| **헤더/타이틀** | 감정원 배너 & 메인 카피 | "유럽 패키지 일정표, 과연 꿀주일까 겉핥기 지옥일까? 1초 만에 감정해드립니다!" + `INSPECTED` 스탬프 |
| **STEP 1** | 일정표 텍스트 입력창 | - `Textarea` 본문 입력 (최대 20,000자 지원)<br>- 실시간 글자 수 카운터 및 상태 뱃지 (`정상` / `주의` / `초과`)<br>- **"✨ 예시 일정표 불러오기"** 원클릭 버튼 (서유럽 3국 8일 실전 데이터 즉시 로드)<br>- `.txt` 텍스트 파일 업로드 지원 (`FileUp`) |
| **STEP 2** | 출발 월 선택 | 1월~12월 계절 드롭다운 (`Select`), 출발 월에 따른 기후/날씨 가치 점수 및 생존 준비물 연동 |
| **STEP 3** | 감정 시작 버튼 | - 빈 입력/글자 수 초과 시 비활성화<br>- 클릭 시 스캔 애니메이션과 함께 `inspectItinerary` 엔진 실행 후 `/result` 페이지로 즉시 이동 |
| **Gemini 키 입력** | 선택적 AI 보조 판독 설정 | 사용자 API 키 입력란(브라우저 `localStorage` 저장), 서버 키 설정 여부 표시. 키가 없으면 룰 엔진 결과만 사용 |
| **보안 공지** | 팩트체크 보안 약속 | 분석은 브라우저 로컬 수행, 일정 원문 전체는 서버에 저장·전송하지 않음, **Gemini 보조 판독 시 모호 문장만 외부 API로 전송됨**을 명시. 근거 없는 "15개국 / 인식률 95%" 안내 문구는 화면에서 삭제함 (KPI #5·#6 검증 후 재게시 여부 결정) |

### 3.2 화면 2: 감정 결과 화면 (`/result` - `app/result/page.tsx`, `components/inspector/result-view.tsx`)

#### 상단 종합 판정 영역 (`VerdictHeader`)
- **해설 연결률 바**: 총 방문지 중 팩트 해설 매칭률(%)을 스트라이프 프로그레스 바로 시각화
- **종합 등급 도장 (`GradeStamp`)**: 종합 가치 점수 기반 스탬프 (`S`, `A+`, `A-`, `B+`, `B-`, `C`) 및 회전 애니메이션
- **한줄 진단 배너**: 일정의 장단점을 풍자적이고 직관적으로 요약 진단 (예: "눈호강 예술투어, 그러나 버스 탑승 28시간의 압박!")
- **사용자 맞춤 뱃지**: 사용자가 직접 입력한 일정 분석 결과일 경우 `[직접 입력한 일정 감정 완료]` 태그 및 `[기본 예시 보기]` 복원 버튼 노출

#### 5대 분석 탭 구성

1. **📋 종합 개요 탭 (`OverviewTab`)**
   - **여정 트랙 (`JourneyTrack`)**: 도시 순서, 숙박 일수(N박), 도시 간 이동수단(항공, 전용버스, 고속열차) 타임라인 띠(도시가 5개를 넘으면 `md` 이상에서도 균형 있게 여러 줄로 줄바꿈하며 줄 바꿈 지점도 이동수단 칩이 얹힌 점선으로 이어진다, 도시명은 최대 2줄 말줄임+`title`, 가로 스크롤 없음) 및 호텔 이동 횟수/이동 피로도 서머리
   - **6대 스탯 육각형 레이더 차트 (`RadarChart`) & 세그먼트 게이지 (`StatGauge`)**:
     1. 문화·역사·예술 (가중치 25%)
     2. 관광 깊이 (가중치 20%)
     3. 이동 부담 (가중치 20%)
     4. 구성의 알참 (가중치 15%)
     5. 자연·경관 (가중치 10%)
     6. 날씨 적합성 (가중치 10%)
   - **방문 국가별 1분 요약**: 국기 플래그, 국가명, 핵심 특징 한줄 코멘트 카드

2. **📅 일정 팩트체크 탭 (`ScheduleTab`)**
   - **일자별 카드 (`DayCard`)**: 일차(DAY N), 방문 도시, 일차별 헤드라인, 식사 구성(조/중/석), 숙박 호텔 정보
   - **일정 항목별 4대 관람 스탬프 뱃지 (`StampBadge`)**:
     - `내부 입장`: 내부 공식 입장 관람 (출처 도메인 링크 배지 포함)
     - `외부 관람`: 건물 외관 포토타임·조망
     - `차창 조망`: 버스/열차 이동 중 차창 관람
     - `판독 불가(원문에 관람 방식 언급 없음)`: 원문에 관람 방식 표기가 없어 확정하지 못한 경우. 억지로 외관/입장으로 확정하지 않는다. 배지 이름 자체가 판독 결과이며 "AI 정밀 판독" 같은 정보 없는 라벨은 쓰지 않는다
   - **판독 근거 문장**: 모든 항목 옆에 원문 근거를 쓴다 (예: `원문에 '(외관)' 표기가 있어 외부 관람으로 판단` / `원문에 관람 방식 표기가 없어 확인 불가`). 내부 로그 문구(`[판단불가] 판정`)는 노출하지 않는다
   - **판독 순서**: ① 원문 괄호 태그 `(외관)/(내부)/(조망)/(전경)/(차창)` (불릿, 없으면 설명 카드 제목) → ② 키워드 규칙 → ③ 둘 다 아니면 `판독 불가`로 두고, 그중 쇼핑을 뺀 줄만 Gemini에 보낸다. Gemini가 답한 항목은 `Gemini 추정(참고용)` 배지가 붙고, `판단불가`로 답하면 그대로 판독 불가다
   - **방문지 카드**: 제목은 설명 문장이 아니라 명소 이름(예: `카펠교`)이다. 원문 불릿 문장은 `원문`으로 함께 보이고, 아래 설명 문단(제목·부제·본문)은 해당 명소 카드 안의 `설명 보기`로 접혀 별도 방문지로 세지 않는다
   - **원문 정리**: 분석 제외 줄을 나열하지 않고 의미 단위로 묶는다 — 날짜/시각/편명/소요시간 줄은 하나의 항공 이동 카드(`✈ 로마(FCO) 출발 → 헬싱키(HEL) 도착 · AY1762 · 소요 3시간 25분`), `국가/도시` 줄은 도시 구간 제목, `…로 이동 _ 약 N 소요`는 이동 줄, `※`·미팅 문구는 유의사항, `예정/HOTEL`·`[조식]…`은 식사·숙박 영역, 소개/안내 카드는 접힘 카드로 이동한다. `펼치기/접기`·`자세히보기` 같은 UI 문구는 화면에서 완전히 숨기되 데이터에는 남는다. 어디에도 못 넣은 줄만 `정리하지 못한 원문 N줄`(기본 접힘)로 모은다. 원문 줄 번호(L-xxx)와 원문 100% 보존은 유지된다
   - **판독 시트 (`SheetContent`)**: Gemini 응답이 있는 항목의 배지를 누르면 원문 문장, 원문 줄 번호(L번호), 근거 키워드, Gemini 응답을 보여 준다 (참고용)

3. **🧾 숨은 비용 영수증 탭 (`ReceiptTab`)**
   - **지그재그 영수증 디자인**: 실제 영수증 용지 질감 및 점선 구분선
   - **기본 패키지 결제가**: 원문 자동 감지 또는 기본 상품가 표기
   - **필수 현지 경비 리스트**: 가이드 경비, 유럽 도시세(City Tax), 식당 매너팁·생수를 항목별로 세 가지 상태로 구분한다 — ① `원문 확인`(금액이 있음, 원문 줄 번호 표시) ② 언급만 있고 금액 없음(예: `가이드 경비: 원문에 '동행하지 않습니다'로만 표기, 금액 없음`) ③ 언급 자체가 없음(`원문에 별도 표기 없음 · 일반적인 평균 €100 (참고용)`). 금액이 없는 항목은 평균 참고값으로 합계에 넣되 "평균 참고값"으로 표시하고, 경고색 대신 중립 안내문(`이 일정표에는 현지 경비 금액이 적혀 있지 않아요. 아래는 유럽 패키지 평균 참고값이며, 실제 금액은 여행사에 확인하세요.`)을 쓴다
   - **선택관광 옵션 실시간 토글**: 항목명은 금액 줄 위의 카드 제목에서, 원문 줄 번호와 함께 모두 표시한다(0건이면 `이 일정표에는 선택관광이 없어요`, 금액만 없으면 그 건수를 안내). 곤돌라, 융프라우 산악열차, 야경투어 등 옵션 체크 시 총 예상 실지출 실시간 연산 및 패키지가 대비 추가 지출액(KRW) 표시

4. **⚖️ 최종 감정서 탭 (`ValuationTab`)**
   - **종합 가치 점수 & `불분명한 항목도 반영해서 재산정` 토글**: 체크 시 관람 방식이 불분명한(판독 불가) 곳을 '내부 입장이 확인되지 않은 곳 = 외부 관람 수준'으로 보수적으로 반영해 관광 깊이 점수를 재산정한다. 설명 문구에는 실제 판독 수치(외부 관람 N곳 / 확인 불가 N곳)가 동적으로 들어간다
   - **여행 취향별 적합도 3종**:
     - 👨‍👩‍👧 부모님 효도 관광 적합도 (버스 이동 시간 및 피로도 기반)

### 4.2 분석 엔진 동작 파이프라인 (`lib/inspector-engine.ts`)
1. **Raw Text 정규화 & 라인 번호 보존**: 원문의 공백 및 개행을 분리하며 정확한 `lineNum` 부여
2. **Day 분할**: `제 N일`, `Day N` 키워드로 일자 블록 분리 및 식사/호텔 메타정보 추출 (`조식 :` 형식과 `[식사]`·`[호텔]` 태그 형식 모두)
3. **전처리 · 분석 제외 플래그** (`lib/itinerary-preprocess.ts`): 날짜 전용 줄, UI 잔여 문구(펼치기/접기·전체보기·더보기 등), 장식 줄, 식사·숙박 태그, 안내(`※`) 줄, 교통·이동 줄은 **삭제하지 않고** 항공 이동 카드·도시 구간·이동 줄·유의사항·식사/숙박 영역·소개 카드·`기타 원문` 중 한 곳에 담는다(UI 문구는 화면에서만 숨김). 원문 줄 번호는 유지되며, 이 줄들은 관람 모드 집계·커버리지·Gemini 전송 대상에서 제외된다. 진단 스크립트(`scripts/debug-inspect.ts`)가 모든 비어 있지 않은 줄이 정확히 한 곳에 담겼는지 검증한다.
   - **카드형 웹페이지 원문**(`자세히보기`가 있는 복사본, `lib/itinerary-structure.ts`): `국가/도시` 줄로 구간을 나누고, 구간 안의 `- ` 불릿만 방문지 본문으로 본다. 불릿 아래의 `제목 / 부제 / 자세히보기 / 본문` 카드는 제목이 불릿 문장에 들어 있는 명소(구간에 불릿이 하나뿐이면 그 명소)에 `설명`으로 접어 넣고, 어느 명소에도 못 붙은 카드는 소개/안내 카드로 둔다. 불릿에 없는 `(외관)`/`(조망)` 태그 제목은 방문지로 올린다. 명소 이름은 설명 카드 제목과 문장 끝의 이름 덩어리로 뽑는다(`extractSightName`). `제목 / 선택관광 / 요금 / 성인 : N유로` 블록은 선택관광 항목(제목 줄이 항목명)으로 읽는다.
   - **식사·숙박**: `[조식]…[중식]…[석식]…`, `예정` 다음 줄(숙소명), `[식사]`/`[호텔]`/`조식 :`/`호텔 :` 형식을 읽는다. 원문에 없을 때만 기본값을 쓰고 화면에 "원문에 없음 · 기본값"으로 표시한다.
4. **도시/국가 매핑**: ① `국가/도시` 줄(불릿이 가장 많은 구간이 일차의 대표 도시) → ② 도시 DB 단어 경계 매칭(앞에 한글이 붙은 "베니스"의 "니스", "비즈니스"의 "니스"는 무시, 긴 키 우선). 지식베이스 출처가 한 도시 것뿐인 명소(두오모→밀라노)는 다른 도시 일정에 출처를 붙이지 않는다.
5. **방문지 후보 판별 및 관람 모드 4대 분류** (`entry`/`exterior`/`window`/`unknown`). 일자당 표시 상한은 없다:
   - **최우선 규칙**: 원문의 괄호 태그 `(외관)`/`(전경)`/`(조망)` → `exterior`, `(내부)`/`(입장)` → `entry`, `(차창)` → `window`. 그다음 운영 문구(`미팅|집결|안내|인솔자|수속` 등)는 방문지에서 제외한다.
   - 방문지 후보: 명소 DB 일치, 관광 탈것(산악열차·곤돌라·유람선 등), 랜드마크 명사, 구체적 활동어(방문·산책·투어 등). 일반 "관광" 단어만으로는 후보가 아님
   - `내부|입장|입장권|투어 포함`, 또는 관광 탈것의 `탑승` → `entry` (단, 항공·버스·열차 탑승은 교통 줄)
   - `외관|전경|포토타임|조망|감상` → `exterior` (`외관 관람`은 `entry`가 아니라 `exterior`)
   - `차창|차안|지나가며`, `버스/열차 관광` → `window`. `출발|도착|이동|경유`는 교통 줄이므로 `window`가 아님
   - 후보이지만 위 어디에도 해당하지 않는 서술 → `unknown` (판독 불가, 근거 `원문에 관람 방식 표기가 없어 확인 불가`). 쇼핑 줄을 뺀 `unknown`만 Gemini 확인 대상이며, 응답은 `inspectItinerary(raw, month, aiVerdicts)`로 다시 반영한다
6. **공식 출처 매칭**: 사전 등록된 공식 도메인 DB(`SIGHTS_SOURCE`)와 매칭하여 사실 출처 부착
7. **동적 비용 및 스탯 계산** (`lib/money-parser.ts`, `lib/receipt-parser.ts`): 상품가는 라벨(상품가·요금 등)이 붙고 범위(50만~2,000만원) 안인 원화 금액을 우선 선택하며, `1,890,000원`·`1890000원`·`189만원`·`₩` 표기를 읽는다. 선택관광·현지경비는 `€`/`유로`/`EUR`/`$`/`£`/`CHF`/원·만원 표기를 읽고 EUR로 환산(가정 환율)하되 원문 통화를 함께 표시한다. 추출 실패 시 사용한 폴백 값(상품가 199만 원, 필수경비 평균 참고값 등)은 브라우저 콘솔에 기록된다. 필수경비는 가이드·도시세·팁 3항목마다 상태(원문 확인/언급만/언급 없음)를 붙인다(`buildMandatory`).
8. **세션 캐싱**: 브라우저 `sessionStorage`에 버전 키(`inspected_result_v3`, `lib/session-cache.ts`)로 직렬화하여 저장, 결과 뷰에서 즉시 동기화. 엔진 출력 형식이 바뀌면 버전을 올려 옛 결과를 읽지 않으며, 버전 키가 없던 옛 캐시는 자동 삭제한다.

## 5. 예외 처리 및 무결성 보장

1. **빈 입력 및 최소 글자수 미달**: 감정 버튼 자동 비활성화 및 안내 텍스트 출력
